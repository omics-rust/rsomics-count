# Read-position projection gate

Fresh projection-source measurement on Apple M2,8 GiB,macOS27.2 arm64,
Rust1.91.0, against official featureCounts2.1.1. This does not inherit the
earlier fraction-correction binary's timings. Both tools use four threads
and the same2,000,000-record BAM,500 genes and1500 exons generated by the
existing fixture generator. Annotation/BAM hashes are retained in samples.json
and in the full packet below; no inputs were regenerated for this run.

Each case has one warmup and five measured pairs, alternating tool order.
Both write complete counts and summaries during timing. Wall time includes
the `/usr/bin/time` subprocess invocation; macOS `-l` supplies peak RSS bytes.
Projection uses extension5=50,extension3=20,read2pos=5. Defaults are also
remeasured on this same new binary.

The source passes a resource-use gate, not throughput: wall time remains
1.43x/1.64x source time. Every native RSS sample is below every source sample
in its case. All12 warmup/measured pairs match every normalized count row and
all assignment-summary categories; each assigns at least1,000,000 records.
This synthetic single-end workload is not a real-cohort or universal result,
nor a timing claim for CI/public-release binaries.
